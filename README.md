# EPID_GRID

**Программа построения иерархической сетки элементарных территориальных единиц для эпидемиологического надзора.**

EPID_GRID формирует воспроизводимую пространственную основу для территориальной привязки, систематизации и последующего анализа эпидемиологических данных. Сетка предназначена для работы со сведениями о случаях заболеваний и предполагаемых местах заражения, результатами энтомологического мониторинга, лабораторных исследований отобранного материала и другими данными, имеющими пространственную привязку.

Сетка строится для заданной полигональной территории, например субъекта РФ, по единой фиксированной схеме. При одинаковых параметрах алгоритма геометрия и идентификаторы одних и тех же ячеек не зависят от того, для какой территории выполняется построение. Это позволяет сопоставлять и объединять результаты независимых расчётов для разных регионов.

Базовые ячейки имеют расчётную площадь **1 км² в системе координат EPSG:3576**. Вблизи 52° с. ш. их линейные размеры приблизительно соответствуют 1 × 1 км. Иерархические идентификаторы позволяют укрупнять пространственные единицы до 4, 16, 64 и 256 км² для адаптации масштаба анализа к особенностям изучаемой инфекции и задачам исследования.

> **Границы функциональности.** Скрипт строит сетку и записывает классификаторы ячеек. Территориальная привязка наблюдений, расчёт эпидемиологических показателей, кластеризация и моделирование активности очагов с использованием внешних факторов выполняются отдельно. Полученная сетка служит пространственной основой для этих задач.

## Возможности

- Построение сетки для активного полигонального слоя QGIS или только для выделенных в нём объектов.
- Единая схема геометрии и кодирования, не привязанная к границам конкретного региона.
- Пять уровней иерархии: L1–L5.
- Дополнительный классификатор широтного объединения соседних ячеек.
- Преобразование исходных границ в рабочую систему координат и попытка исправления некорректных геометрий.
- Пакетная запись результатов в GeoPackage, отображение хода расчёта и возможность отмены.
- Автоматическое добавление выходного слоя в проект QGIS.

## Область применения

Сетка может использоваться для пространственного учёта и сопоставления данных о различных инфекциях, объединения результатов мониторинга из нескольких источников, подготовки карт и последующего анализа на разных территориальных уровнях. К ячейкам могут быть присоединены характеристики окружающей среды и другие внешние факторы для дальнейшего моделирования.

Программа предназначена для использования при организации эпидемиологического надзора с учётом действующих методических указаний. Применимость выбранной геометрии, размеров ячеек и способа агрегации к конкретной задаче следует оценивать по соответствующему документу. Само использование EPID_GRID не является подтверждением нормативного соответствия всего аналитического процесса.

## Требования

Необходимы **QGIS Desktop 3.x** со встроенной средой Python 3 и PyQGIS, исходный полигональный слой с корректно определённой системой координат и доступная для записи папка для результата.

Скрипт использует библиотеки QGIS и Qt, доступные в среде QGIS. Отдельная установка сторонних Python-пакетов для приведённого исходного кода не требуется. Запуск рассчитан на открытое приложение QGIS: скрипт обращается к активному слою и интерфейсу `iface`.

Минимальная поддерживаемая версия QGIS и перечень проверенных конфигураций в исходном коде не указаны. Перед обработкой большой территории рекомендуется проверить работу на небольшом участке.

## Быстрый запуск

1. Скачайте файл [`EPID_GRID.py`](EPID_GRID.py) из репозитория.
2. Откройте QGIS и добавьте полигональный слой границ исследуемой территории.
3. Сделайте слой границ активным, щёлкнув по его названию в панели слоёв.
4. Если нужна сетка только для части объектов слоя, выделите их. Если нужен весь слой, снимите выделение.
5. Откройте **Модули → Консоль Python**. В стандартной конфигурации также доступно сочетание `Ctrl+Alt+P`.
6. В консоли нажмите **Показать редактор**, затем откройте `EPID_GRID.py`.
7. Нажмите **Выполнить скрипт** (`Ctrl+Shift+E`).
8. В диалоге сохранения укажите путь и **новое имя** файла `.gpkg`.
9. Дождитесь завершения расчёта. Созданный слой будет добавлен в проект под названием **«Сетка»**.

Порядок работы с редактором описан в [документации консоли Python QGIS](https://docs.qgis.org/latest/en/docs/user_manual/plugins/python_console.html).

> При наличии выделения скрипт обрабатывает **только выделенные объекты**. Положение и масштаб отображаемой карты не ограничивают территорию расчёта.

Скрипт запускается сразу при выполнении файла: вызов `generate_grid()` уже находится в конце исходного кода. Устанавливать его как плагин QGIS не нужно.

## Входные данные

На вход подаётся активный векторный слой с геометрией Polygon или MultiPolygon и определённой системой координат. Это могут быть административные границы, контур исследуемой территории или несколько полигональных участков.

Исходный слой не обязательно заранее перепроецировать в EPSG:3576: преобразование выполняется при расчёте. Однако система координат источника должна быть **правильно определена**, а не просто назначена произвольно.

По умолчанию скрипт пытается исправить некорректные геометрии. Если после исправления объект остаётся некорректным или перестаёт быть полигональным, выполнение прекращается с сообщением об ошибке. Исходный слой при этом не редактируется.

## Выходные данные

Результат сохраняется в **новый файл GeoPackage** с полигональным слоем `grid_1km` в системе координат **EPSG:3576 — WGS 84 / North Pole LAEA Russia**. Для слоя создаётся пространственный индекс.

| Поле | Тип | Содержание |
| --- | --- | --- |
| `ID_L1` | Строка | Уникальный идентификатор базовой ячейки площадью 1 км² |
| `ID_L2` | Строка | Идентификатор родительской единицы уровня L2, 4 км² |
| `ID_L3` | Строка | Идентификатор родительской единицы уровня L3, 16 км² |
| `ID_L4` | Строка | Идентификатор родительской единицы уровня L4, 64 км² |
| `ID_L5` | Строка | Идентификатор родительской единицы уровня L5, 256 км² |
| `Area_km2` | Вещественное число | Площадь геометрии базовой ячейки в EPSG:3576, выраженная в км² |
| `MERGE_N` | Целое число | Размер группы широтного объединения: 1, 2 или 4 базовые ячейки |
| `MERGE_ID` | Строка | Идентификатор группы широтного объединения |

Атрибуты исходных полигонов в выходной слой не переносятся. Во время построения создаются только базовые ячейки L1; отдельные геометрии крупных уровней автоматически не формируются.

## Иерархия ячеек

Каждый следующий уровень объединяет четыре единицы предыдущего уровня. Идентификаторы всех уровней записаны в атрибуты каждой базовой ячейки.

| Уровень | Площадь полной единицы | Число базовых ячеек | Поле группировки |
| --- | --- | --- | --- |
| L1 | 1 км² | 1 | `ID_L1` |
| L2 | 4 км² | 4 | `ID_L2` |
| L3 | 16 км² | 16 | `ID_L3` |
| L4 | 64 км² | 64 | `ID_L4` |
| L5 | 256 км² | 256 | `ID_L5` |

Идентификатор состоит из корневого кода блока `R…T…` и, для уровней L1–L4, последовательности цифр от 1 до 4, задающей положение внутри блока. Укорочение этой последовательности определяет переход к родительскому уровню; L5 соответствует корневому блоку.

Для получения полигонов более крупного уровня используйте инструмент QGIS **Dissolve / «Объединение»** с группировкой по нужному полю. Например, для L3 выберите `ID_L3`. Принцип операции описан в [документации QGIS](https://docs.qgis.org/latest/en/docs/user_manual/processing_algs/gdal/vectorgeoprocessing.html).

**Площади в таблице относятся к полным группам.** У границы исследуемой территории в результат могут попасть не все базовые ячейки родительской единицы. Объединение имеющихся ячеек не восстанавливает отсутствующие части, поэтому площадь такого объекта может оказаться меньше площади полного уровня.

## Широтное объединение

Кроме основной иерархии, скрипт записывает классификатор группировки ячеек по угловому направлению в пределах одного радиального ряда. Размер группы определяется по широте середины ряда.

| Широта середины ряда | `MERGE_N` | Полная группа |
| --- | --- | --- |
| Менее 60° с. ш. | 1 | Одна базовая ячейка, 1 км² |
| От 60° до менее 70° с. ш. | 2 | Две соседние базовые ячейки, 2 км² |
| От 70° с. ш. | 4 | Четыре соседние базовые ячейки, 4 км² |

Для создания геометрий этих групп выполните Dissolve по `MERGE_ID`. В исходном результате геометрии остаются базовыми, а `Area_km2` описывает площадь отдельной ячейки, не всей группы.

Широтное объединение и уровни L1–L5 — **разные схемы группировки**. Например, группа `MERGE_N = 4` состоит из четырёх ячеек одного ряда, а единица L2 формируется иерархическим объединением по двум направлениям. Для групп у края территории также возможна неполная представленность.

## Геометрия и воспроизводимость

Алгоритм использует радиально-секторную схему в полярной равновеликой проекции EPSG:3576. Базовые ячейки образуются пересечением радиальных направлений и рядов с шагом по квадрату радиуса; границы между вершинами записываются прямыми отрезками в рабочей проекции. Шаги рассчитываются так, чтобы площадь базовой полигональной ячейки составляла 1 000 000 м² с учётом численной точности вычислений.

Это **не сетка строго квадратных ячеек**. Площадь и форма необходимо различать: площадь задаётся алгоритмом, а линейные размеры, соотношение сторон и искажения расстояний зависят от положения. Ориентир «около 1 × 1 км на 52° с. ш.» не означает метровой точности сторон на местности.

Официальная область применения [EPSG:3576](https://epsg.org/crs_3576/WGS-84-North-Pole-LAEA-Russia.html) — Северное полушарие севернее 45° с. ш. «Произвольная территория» здесь означает выбор полигонального контура, а не подтверждённую пригодность алгоритма для любой точки земного шара. Для территорий за пределами области применения и для приполюсных участков требуется отдельная проверка геометрии и пригодности сетки к задаче.

Границы региона используются только для отбора ячеек, а не как начало отсчёта сетки. Для независимых расчётов должны совпадать версия алгоритма, рабочая система координат и параметры построения. Сравнивать координаты следует с обоснованным численным допуском, а не по побайтовому равенству файлов.

## Границы территории

В результат включаются **целые ячейки, пересекающие исходные полигоны**, в том числе при касании границы. Обрезка ячеек по контуру территории не выполняется. Поэтому выходная сетка может немного выходить за административную границу.

Обрезку можно выполнить отдельно, но после неё геометрия и площадь граничных фрагментов изменятся. Такие фрагменты нельзя описывать как полные базовые ячейки площадью 1 км².

При независимом построении для соседних или перекрывающихся территорий одна и та же ячейка может присутствовать в нескольких файлах. После объединения слоёв оставьте одну запись на `ID_L1` и проверьте согласованность геометрий. До расчёта сумм и числа наблюдений дубликаты должны быть исключены.

## Настройки

Основные параметры расположены в начале `EPID_GRID.py`.

| Параметр | Значение по умолчанию | Назначение |
| --- | --- | --- |
| `TARGET_CRS` | `"EPSG:3576"` | Рабочая система координат |
| `REFERENCE_RADIUS_M` | `4_135_000.0` | Опорный радиус для определения углового шага |
| `BASE_AREA_M2` | `1_000_000.0` | Расчётная площадь базовой ячейки, м² |
| `BLOCK_SIZE` | `16` | Размер корневого блока по каждому индексу |
| `BATCH_SIZE` | `5000` | Число объектов в пакете записи |
| `OUTPUT_LAYER_NAME` | `"grid_1km"` | Имя слоя в GeoPackage |
| `REPAIR_INVALID_GEOMETRIES` | `True` | Попытка исправления некорректных исходных геометрий |
| `UI_INTERVAL_SECONDS` | `0.3` | Интервал обновления интерфейса, с |
| `MERGE_LATITUDE_2` | `60.0` | Порог включения групп из двух ячеек |
| `MERGE_LATITUDE_4` | `70.0` | Порог включения групп из четырёх ячеек |

Не изменяйте геометрические параметры, если нужна совместимость с ранее построенными сетками. Изменение широтных порогов меняет классификатор `MERGE_ID`, хотя само по себе не изменяет геометрию базовых ячеек.

`BLOCK_SIZE = 16` согласован с четырьмя разрядами кода и пятью уровнями L1–L5. Его изменение требует пересмотра логики кодирования, а не только замены одной константы. Замена `TARGET_CRS` также не является универсальным способом переноса алгоритма в другую проекцию: расчёт использует её полярную структуру и начало координат.

## Проверка результата

После завершения убедитесь, что слой находится в EPSG:3576, значения `Area_km2` близки к 1, идентификаторы `ID_L1` уникальны, а территория покрыта без непредусмотренных пропусков. Для проверки межрегиональной совместимости можно независимо построить сетки для перекрывающихся участков и сопоставить геометрию ячеек с одинаковым `ID_L1`.

Скрипт не переносит наблюдения в ячейки автоматически. При последующем пространственном присоединении нужно отдельно определить правило для точек на общих границах: одна точка не должна учитываться несколько раз из-за пересечения соседних полигонов.

## Ошибки и отмена

| Ситуация | Что проверить |
| --- | --- |
| «Выберите корректный векторный слой границ» | Загружен ли векторный слой и выбран ли он в панели слоёв |
| «Активный слой должен быть полигональным» | Не выбран ли точечный, линейный или растровый слой |
| «У исходного слоя не определена система координат» | Корректно ли определена система координат источника |
| «Файл уже существует» | Указано ли новое имя GeoPackage: существующий файл не перезаписывается |
| Ошибка геометрии | Исправьте исходные объекты средствами QGIS и повторите расчёт |
| `No module named 'qgis'` | Запускается ли файл во встроенной среде QGIS, а не в обычном Python |
| Расчёт занимает много времени | Начните с небольшого участка; учитывайте размер территории, сложность границ и скорость записи |

При отмене после начала генерации уже созданные объекты сохраняются, а результат добавляется как **«Сетка_неполная»**. Такой слой не является законченным покрытием. При ошибке оставшийся файл также может быть неполным. Автоматического продолжения расчёта с места остановки нет; для повторного запуска укажите новое имя файла.

Технические сообщения и сведения о ходе выполнения выводятся в консоль Python QGIS.

## Воспроизводимость исследования

Для публикации или передачи результатов сохраняйте версию либо хеш коммита `EPID_GRID.py`, значения параметров, версию QGIS, источник и дату получения границ, а также сведения об использованном выделении объектов. Дополнительно фиксируйте выполненные после построения операции: удаление дубликатов, обрезку, объединение ячеек и правила присоединения наблюдений.

Использование одинаковой сетки само по себе не обеспечивает одинаковые результаты анализа: они зависят от полноты наблюдений, качества координат, способа расчёта показателей и выбранного масштаба агрегации.
